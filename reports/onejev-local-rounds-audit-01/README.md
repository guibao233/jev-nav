# OneJev-4B 本地两轮导航核查

核查 `local-round-01`、`local-round-02` 共 18 个已完成任务：三条固定路线 × 三种深度文字输入 × 两轮。18/18 均为带当前目标标记的 GS RGB 图片＋文字输入；18/18 均失败，结束原因均为 `action_budget`。本次只读取历史记录，在 CPU 上重算指标，没有调用模型、启动渲染器或改动导航策略。

## 多模态输入是否生效

全部 **5,100 次决策**同时满足：

- 保存的 `frames/*-model-rgb.jpg` 与 `image_input.sha256`、字节长度和 640×480 JPEG 格式一致。
- 独立重建包含 `state.visual.image="<image:1>"` 及 JPEG Base64 `media` 的实际请求，其 SHA256 同时匹配 `wire_request_sha256` 和 `decision.request_body_sha256`。
- 本地服务的每次成功响应均返回 `decision.response.qev.media.images=1`、`videos=0`，实际模型名称为 `OmniJev/OneJev-4B`。
- 服务端多模态代码先加载媒体，再交给图像处理器和视觉模型计算；不是仅传入图片文件名。可检查 [mm_engine.py](../../local_models/onejev-4b/source/qev/mm_engine.py) 的 `_prepare`、`_set_media`、`decide`。

`none` **仅移除深度文字**，仍然有当前 RGB、目标/路径文字、机器人状态与历史。因此它不是纯文字输入，也不是完全无视觉感知。

数值组发送 9 个角度区域的深度摘要；语义组发送语言距离分档和观测状态。本次逐步检查了语义转换与保留的数值调试数据一致。三组使用相同固定任务、相同步长与成功阈值；部署清单哈希也一致。服务为本机 `http://127.0.0.1:8011/v1/systemone`，`fork_mode=batched`、`prompt_version=qev-labels-v2`。

简单路线：数值和语义组完全没有转身，主要前后往返。两者曾接近到 0.578 m，却没有进入 0.30 m 的成功范围；累计移动约 25 m 后失败。无深度文字组也出现往返，另连续左转 38 次。

复杂路线：数值和语义组走了 43.248、55.494 m，但最终剩余距离比起点还大；主要是局部往返而非有效绕过转角。无深度文字组末尾连续原地左转 241 次，占预算的 96.4%。

长路线：语义组累计走了 113.144 m，最终仍剩 16.467 m，表现为大量前后移动。数值组末尾连续左转 324 次；无深度文字组末尾连续左转 474 次，占预算的 94.8%。后两者陷入长时间原地旋转。无深度文字组较少碰撞主要伴随较少平移，不能解释为导航避障更强。

局部目标在机器人后方时仍选择前进的决策也存在，详见 `audit.json` 的 `forward_with_target_behind_steps`。这记录了决策与目标几何方向不一致的现象，但不足以确定是动作标签、提示词格式、模型能力或其他原因造成。

## 图片标记的实际呈现

5,100 次决策中，目标投影在画面内仅 **4 次**；2,156 次在画面范围之外，2,940 次在相机后方。因此 **5,096 次使用画面边缘方向箭头**，只有 4 次是画面内的目标点标记。所有请求时相机俯仰均为 0°，模型没有主动调整俯仰。

这意味着本批主要测到的是“RGB 环境＋目标边缘箭头＋导航文字”的决策，而不是持续在 RGB 内看到目标点的视觉跟随。局部目标较近且标在脚下高度，平视相机可能使目标投影低于画面；转向不当又会使目标落在身后。多模态传输及服务端处理已经核实，但这些记录不能证明模型有效利用了图像，更不能单凭本批判断其一般视觉导航能力。

## 判断与复核范围

在当前提示词、目标标记方式和三条固定路线设置下，OneJev-4B 尚未表现出可靠的路径跟随、恢复和到达能力。三种深度输入均为 0/6 成功，不能按成功率给它们排序；语义深度也没有解决往返问题。两轮逐步概率和轨迹完全一致；本地 Qev 用最高概率动作作选择，因此重复运行没有带来新的轨迹样本，不应视为跨随机起点/朝向的独立验证。

本次在 CPU 上重新计算了每步 NavMesh 距离、累计位移、碰撞与无效动作计数、停止成功条件及延迟分位数；检查了位姿连续性、固定任务一致性、所有请求图片及传输哈希，并在完成后重新检查源文件哈希未改变。共 5,100 次成功响应、5,100 次请求尝试，没有日志所示的重试。失败结束原因均是动作预算耗尽，未见本批记录中的 API/模型加载错误。

[audit.json](audit.json) 保存逐任务动作/标记统计、两轮一致性、配置与原始文件哈希；[audit.py](audit.py) 是可重跑的只读核查程序。使用 Habitat 环境并传入一个新的输出目录，例如：

```bash
conda activate habitat-gs
python reports/onejev-local-rounds-audit-01/audit.py /tmp/onejev-rounds-recheck
```

该命令不会启动 GPU 渲染或发送模型请求。部署清单中的 `prepared_gpu_validation_pending` 是部署准备时保留的状态；本报告以两轮实际成功响应为推理已运行的证据，未回写历史部署清单。
