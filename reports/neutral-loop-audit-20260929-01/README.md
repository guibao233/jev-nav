# neutral-02 原地转向与路径进度审核

结论：确认存在持续的原地转向循环。第 85 步后机器人没有再发生平移，第 86–250 步共 165 步停在同一位置；161 次转向、4 次低头，其中一次低头超限。循环期间没有请求前进或后退，不能将这段零位移解释为移动动作被仿真器拒绝。NavMesh 离线检查存在可移动方向。

本报告步号从 1 开始，对应 steps.jsonl 的 step + 1。只读取已有日志、图像和 NavMesh，未修改导航代码、配置或历史记录；未启动 GPU 渲染器、未请求 Jev。

## 循环发生过程

- 第 1–4 步为后退，开始朝参考路径方向取得进展；本轮并非从一开始一直走反。
- 第 59 步是整轮唯一碰撞：后退只完成约 0.190 m，之后继续移动，未在此卡死。
- 第 62 步参考路径进度达到 2.545541 m，此后保持到结束，current_target 世界位置随之固定。
- 第 85 步仍成功前进 0.25 m，无碰撞。之后位置一直为 `[-7.702047348, -0.125, -10.575712204]`。
- 第 86–250 步：80 次左转、81 次右转、4 次低头，没有任何平移尝试；占整个动作预算的 66%。
- 第 93、97、99 步分别低头到 15、30、45 度；第 109 步再次低头触发俯仰上限，记无效。
- 第 198–250 步连续 53 次严格左右交替，在约 82.70° 与 97.70° 两个身体朝向间往返。整个停滞阶段只访问了约 82.70°、97.70°、112.70°、127.70° 四个朝向。

## 输入与执行层核实

停滞的全部 165 份请求均为 `move_forward.status=blocked`、`move_backward.status=unknown`。后退候选一直存在，当前中性后退描述和明确停止规则确实进入所有请求。模型持续偏好转向，后退概率中位数 0.10，范围 0.06–0.18；最终没有选择后退。只看概率不能证明模型内部推理过程，但足以确认有后退能力而未使用。

第 150 步右转时，后退概率 0.09、右转 0.33、左转 0.28；第 151 步又转回左侧。最近五步历史已包含相反转向与零平移，并不是完全没有反馈。历史中的 `success=true` 表示动作被正常执行，不表示导航取得进展；当前没有把“近五步净位移为零、相反转向重复”归纳成独立停滞信号。原提示已经有避免无进展的相反动作交替的句子，本轮该提醒没有阻止循环。

第 85、86、150、151 步的 depth_facts 从保存的原始深度重新计算后与真实请求精确一致，排除了这几步日志遗漏或深度摘要未送入模型的解释。第 150 步 RGB 目视为近处有盆栽的柜体/架体；模型实际读取的是 mesh 深度摘要，GS RGB 仅用于回放，不能以 RGB 外观代替几何判定。

在循环位置，仅用原 NavMesh 的 `try_step` 检查四个实际朝向：

这些是 CPU 上的运动过滤查询，不是新的一轮真实模型控制，也不保证 mesh 几何上的全程无碰撞。前进部分朝向存在约束，符合近障碍处需要恢复的情形；后退均可完整执行，说明没有被 NavMesh 锁在不可脱离的位置。所有探测终点仍在可通行区域。

## 目标更新滞后是另一个已确认的问题

当前 RoutePreview 只在旧进度前方一个较小区间内投影，并且仅在距离该局部区间不超过 0.5 m 时推进。偏离该窗口后，即使重新靠近原路线更后面的部分，也没有重新关联流程。

本轮逐帧重算 250 个 reference 与日志精确一致，确认这是当前进度规则的结果。最终位置的几何情况：

| 量 | 数值 |
|---|---:|
| 跟踪器记录的路线进度 | 2.546 m |
| 在整条原路线上的最近点进度 | 4.757 m |
| 距整条原路线最近点 | 0.0468 m |
| 输入中的 distance_from_local_reference_m | 1.812 m |
| 仍提供的 current_target 路线进度 | 3.296 m |
| 距该旧 current_target | 1.463 m |

这里 1.812 m 衡量的是到受限局部窗口的距离，不能解释为离整条路径 1.812 m。机器人实际上已经靠近后续路段，当前目标却仍在沿路径走过的方向上，要求它折返。目标相对方位仍随身体转动正确更新；冻结的是路径进度及目标世界位置。

CPU NavMesh 检查显示，当前位置到最近原路线点可直接连接，约 0.0468 m；到旧目标也仍可达，约 1.463 m。因此旧目标不是不可达，但已经滞后。[局部地图](local-map.png)显示机器人、旧目标、后续最近路线点和四个反复访问的朝向。

## 解释与下一步优先级

直接失败机制是：近障碍的前进提示始终为 blocked、后退为 unknown，模型在少数朝向间往返；正常执行的转向没有转化为平移。当前短期输入只列动作结果，虽然已有避免循环的提示，但没有帮助该次模型跳出循环。

目标滞后是同时存在的上游问题，会使当前目标与后续预览/最终目标的方向分离，增加跟随困难。日志不能单独证明它造成了每次转向，需通过独立对照区分目标更新与动作策略的贡献。

建议先讨论：

1. 路径进度失联后，如何在检查连接可通行、避免跨墙跳段的前提下，重新关联原路线后续段；不要直接不加约束地跳到欧氏最近点。
2. 从最近五步自身动作生成净平移、净转角、相反转向次数等停滞摘要；明确动作执行成功与导航进展的区别，仍由 Jev 选择下一步，不自动替换为恢复动作。
3. 再对比深度语义表达与带安全余量的路径。本轮证据不支持仅靠增加预算或再次加入后退即可解决：后退已存在，最终 165 步没有使用。

以上均为审核后的建议，未实施策略修改。中性描述恢复后本轮已能初步推进，但不能用这一条实验推导总体成功率变化。
